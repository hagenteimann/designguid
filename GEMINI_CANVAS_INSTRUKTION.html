01 · Kern-Philosophie

1Grundprinzipien

Jedes Push8-Projekt folgt vier unverhandelbaren Prinzipien:

  • Token-System zuerst. Kein einziger hardcodierter Wert für Spacing, Farbe oder Radius. Nur CSS Custom Properties.
  • Mobile First. Design beginnt bei 375px. Desktop ist die Erweiterung – nie umgekehrt.
  • Kein generisches Design. Inter + lila Gradient + weiße abgerundete Cards = verboten.
  • DSGVO by Default. Kein CDN ohne Prüfung. Fonts lokal. Icons inline.
Entscheidungs-Hierarchie 1. Explizite User-Anweisung
2. PROJEKT_BRIEF.md (Projektziele)
3. Verbindliche Regeln (Rules)
4. Design System Spezifikation
5. Branchenstandards / Best Practices

Bei Konflikten: immer höher in der Hierarchie gewinnt. Bei Unklarheit → fragen, nicht raten.

Interaktive Pflicht-Features

Logo – SVG-Download (1 Klick) Jede Logo-Variante bekommt einen Download-Button. Klick → SVG-Datei. Kein Rechtsklick nötig. 
function downloadSVG(id, filename) {
  const svg = document.getElementById(id);
  const blob = new Blob([svg.outerHTML],
    { type: 'image/svg+xml' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url; a.download = filename;
  a.click(); URL.revokeObjectURL(url);
}
Farbe – Hex in Zwischenablage (1 Klick) Jeder Farb-Swatch hat einen Copy-Button. Klick → Hex-Wert in Clipboard. 1,5 Sek. „Kopiert!"-Feedback. 
function copyColor(btn, value) {
  navigator.clipboard.writeText(value)
    .then(() => {
      const orig = btn.textContent;
      btn.textContent = 'Kopiert!';
      btn.classList.add('copied');
      setTimeout(() => {
        btn.textContent = orig;
        btn.classList.remove('copied');
      }, 1500);
    });
}

Single-File Prinzip (kritisch)

Das CD-Manual = 1 HTML-Datei, offline funktionsfähig Keine externen Links. Alles inline. Muss per Doppelklick im Browser öffnen – ohne Internet.
  • Fonts als base64 Data URI eingebettet (nicht CDN, nicht relativer Pfad)
  • Icons als Inline SVG direkt im HTML
  • Alle Styles im <style>-Tag
  • Alle Scripts im <script>-Tag
  • Kein <link>, kein <script src="..."> zu extern

Font als base64 einbetten (Windows)

[Convert]::ToBase64String(

    "inter-regular.woff2"
  )
)

08b · Bildsprache & Foto-Empfehlungen

★Sektion 09b – bei Website-Rebuild Pflicht

Trigger: Agent erhält eine bestehende Website als Referenz Sobald eine alte Website-URL oder ein Screenshot übergeben wird, analysiert der Agent Branche, Farbwelt und Tonalität – und dokumentiert im Design System konkrete Bildmotive. Keine generischen Stock-Beschreibungen.

1 · Produktmotive

Wie sollen Produkte oder Leistungen fotografiert werden?

  • Perspektive (Vogelperspektive, Eye-Level, Detail)
  • Hintergrund (freigestellt, Farbe aus Palette, Textur)
  • Lichtstimmung (seitliches Licht, diffus, dramatisch)
  • Styling (roh/authentisch vs. clean/minimalist)

2 · Unternehmensmotive

Team, Räume, Prozesse – keine Stock-Klischees.

  • Team bei echter Arbeit – kein Lächeln in Kamera
  • Räumlichkeiten im echten Zustand
  • Behind-the-Scenes, Prozesse, Handwerk
  • Explizit benennen was nicht passt

3 · Farbwelt & Mood

Welche Lichtstimmungen passen zur Primärfarbe?

  • Warmton / Kaltton / Neutral festlegen
  • Kontrast-Level (flach, mittel, dramatisch)
  • Verbotene Stile (HDR, blaue Filterstiche, Whitebox)
  • 5–8 Unsplash/Pexels-Suchbegriffe ausgeben

Was der Agent bei Übergabe einer alten Website analysiert

AnalyseAbleitung
Branche / KategorieGrundtonalität der Bildsprache (rau vs. clean vs. seriös)
Primärfarbe der MarkePassende Lichtstimmung (warm, kalt, neutral)
ZielgruppeAuthentizitätsgrad (Handwerk → echt, roh / SaaS → clean, hell)
Bestehende BildspracheWas beibehalten, was verbessert werden soll
Anti-Motive immer explizit benennen Nicht nur was gut passt – sondern auch was ausdrücklich nicht passt. Beispiel: „Keine lachenden Business-Menschen mit Laptop im Café", „Keine blauen Farbstiche", „Kein HDR".
